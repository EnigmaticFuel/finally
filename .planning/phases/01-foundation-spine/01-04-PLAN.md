  <name>Task 1: Line-ending policy — .gitattributes and a renormalized index</name>
  <precondition>The working tree is clean before renormalizing. `git add --renormalize .` stages content across the whole repository, so any unrelated uncommitted edit would be swept into the normalization commit. Commit or stash outstanding work first.</precondition>
  <reversibility rating="costly">Renormalization rewrites the stored content of every text file in the index in one commit. Undoing it means reverting that commit across the whole tree, and any branch created before it will conflict on line endings when merged.</reversibility>
  <files>.gitattributes</files>
  <read_first>
    - .gitignore — the existing ignore rules, so the new attributes do not contradict them
    - .planning/phases/01-foundation-spine/01-RESEARCH.md — the `.gitattributes` Code Examples block and the quoted git-scm semantics for `text`, `eol` and `-text`
    - .planning/PROJECT.md — the Key Decisions table recording the tracked `db/finally.db` as an accepted risk, which is what makes the binary exclusion load-bearing rather than decorative
    - planning/PLAN.md section 11 — the start and stop scripts Phase 2 will add for macOS, Linux and Windows PowerShell
  </read_first>
  <action>
Create `.gitattributes` at the repository root. It currently does not exist — `git ls-files` confirms no such file is tracked.

Set `* text=auto` as the baseline so git normalizes text content to LF in the index.

Then pin the paths where the working-tree ending actually matters. Shell scripts and the Dockerfile take `text eol=lf`, because a `.sh` checked out with CRLF fails on macOS and Linux with a bad interpreter error on the shebang line — that is the specific failure SETUP-03 exists to prevent, and Phase 2 adds `scripts/start_mac.sh` and `scripts/stop_mac.sh`. Cover `*.sh`, `Dockerfile` and `*.dockerfile`. PowerShell and Windows batch files take `text eol=crlf`: cover `*.ps1`, `*.bat` and `*.cmd`, for Phase 2's `scripts/start_windows.ps1` and `scripts/stop_windows.ps1`. Note that specifying `eol` automatically sets `text` where `text` was left unspecified, so these lines are complete as written.

Then unset text handling on binary paths with `-text`, which tells git not to attempt any end-of-line conversion on checkin or checkout. Cover `*.db` and `*.png`. The `*.db` rule is the one that matters here and it is a correctness fix rather than tidiness: `db/finally.db` is a tracked binary SQLite file, and a bare `text=auto` invites git to inspect it and potentially convert byte sequences inside it. Put this rule in the same file and the same commit as the `text=auto` line so there is no window in which the baseline applies without the exclusion.

Then, from a clean working tree, stage the normalization with `git add --renormalize .` and inspect `git status` to see exactly what git intends to rewrite before committing. Confirm before committing that `db/finally.db` is not among the files staged for content change — if it appears, the `-text` rule is not matching and must be fixed before the commit lands, not after.

Do not add an `.editorconfig` as a substitute or a supplement here. Git attributes enforce this repo-wide regardless of each developer's `core.autocrlf` setting, which an editor configuration cannot do.
  </action>
  <verify>
    <automated>git ls-files --eol .gitattributes | grep -q "w/lf"</automated>
    <automated>git check-attr text eol -- Dockerfile scripts/start_windows.ps1 db/finally.db</automated>
  </verify>
  <acceptance_criteria>
    - `.gitattributes` exists at the repository root and is tracked: `git ls-files .gitattributes` outputs `.gitattributes`
    - `.gitattributes` contains `* text=auto`
    - `.gitattributes` contains an `eol=lf` rule matching `*.sh` and one matching `Dockerfile`
    - `.gitattributes` contains an `eol=crlf` rule matching `*.ps1`
    - `.gitattributes` contains a `-text` rule matching `*.db`
    - `git check-attr eol -- scripts/start_windows.ps1` reports `eol: crlf`
    - `git check-attr eol -- Dockerfile` reports `eol: lf`
    - `git check-attr text -- db/finally.db` reports `text: unset`
    - `git ls-files --eol db/finally.db` shows `w/-text` and `i/-text`

    - `git status --porcelain` is clean after the renormalization commit
  </acceptance_criteria>

Note that `backend/app/llm/` and `backend/app/services/` will be empty directories after this and stay empty until Phase 3 and Phase 6 fill them. Leave them in place; git does not track empty directories, so nothing needs doing about them.
