<objective>
Close the three findings that live on the portfolio read and reset paths: WR-02 (the reset
endpoint is cross-site forgeable), WR-04 (the reset reports a hardcoded body instead of the state
it wrote) and IN-05 (`unrealized_pnl_percent` divides by an unguarded cost basis).

Purpose: WR-02 is a genuine threat-model item, not a cleanup. `POST /api/portfolio/reset` takes no
body, no header and no token, and the app has no auth, no CORS configuration and no origin check,
so a cross-origin HTML form POST - a CORS "simple request" that fires no preflight - lands the
destructive side effect from any tab the user has open while the container is running. `GET` is
already refused, which closes prefetch and navigation but not this vector. WR-04 and IN-05 are the
honesty half: a response that asserts its own content cannot report a regression, and an unguarded
division takes down the entire `GET /api/portfolio` read rather than one position.

Output: `ResetRequest` in `app/api/models.py`; a reset route that requires it; `reset_portfolio`
taking the price cache and returning `await get_portfolio(...)`; a zero-cost-basis null in
`value_portfolio`; and tests at both the service and route level, every one of which fails against
today's code.
