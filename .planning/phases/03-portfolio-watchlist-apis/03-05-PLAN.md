Make portfolio value accumulate on its own. A lifespan-owned `snapshot-loop` task records
total value every 30 seconds and skips the write when the cents-rounded total is unchanged.
Then reconcile the phase: publish the services package surface against what all four plans
actually built, close the test-fixture hole a background writer opens, and take the whole
suite green.

a request. Everything before it happens because a user did something; this happens because
time passed, which is what gives Phase 5's P&L chart a line rather than a scatter of trade
events. It is also the phase's reconciliation pass: `app/services/__init__.py` deliberately
lagged through wave 2 so three parallel plans would not collide on one file, and this plan
is where it catches up in a single write.

callable loop body and the one transaction; `main.py`'s lifespan owning the task; the

Create `backend/app/services/snapshots.py`. Module docstring stating what it owns and the why:
this is the only writer in the app that runs because time passed rather than because a request
arrived, which is what gives the P&L chart a continuous line instead of a scatter of trade
events. `from __future__ import annotations` first, then `asyncio`, `logging`, `sqlite3`,
`pathlib.Path`; `from app.db.connection import run_db, writing`; `from app.db.money import
round_money`; `from app.db.queries import get_latest_snapshot, get_positions, get_profile,
insert_snapshot`; `from app.market import PriceCache`; `from .portfolio import value_portfolio`.
One `logger = logging.getLogger(__name__)`. Use `# --- Recording ---` and `# --- The loop ---`
dividers. Compose existing query functions and write no SQL.

Declare one module-level constant in `SCREAMING_SNAKE_CASE`: `SNAPSHOT_INTERVAL_SECONDS = 30.0`.
PLAN.md section 7 fixes the 30 seconds; naming it once means the tests and the loop cannot
disagree, and a reader sees the number without reading the loop.

Define `def _record_if_changed(conn: sqlite3.Connection, prices: dict[str, float]) -> bool` — a
plain `def` taking the connection first, matching every function in `queries.py`. Everything
happens inside one `with writing(conn):` block, in this order: `get_profile(conn)`;
`get_positions(conn)`; `value_portfolio(profile["cash_balance"], rows, prices)` for the total;
`get_latest_snapshot(conn)`; then the decision — when the latest row exists **and**
`round_money(total) == round_money(last["total_value"])`, record nothing; otherwise
`insert_snapshot(conn, total)`. Set one local flag rather than returning from inside the block,
and `return` it once after the block, so the transaction has exactly one exit and the
read-compare-write is one visibly bounded unit. Pass the unrounded `total` to `insert_snapshot`:
`round_money` decides the comparison only, and `money.py`'s docstring forbids rounding a value
you store.

Wrapping reads in `writing()` here is deliberate and is the one place in this phase that departs
from `connection.py`'s "reads do not use `writing`" note — because this is not a read, it is a
read-modify-write on the same rows `execute_trade` touches. `BEGIN IMMEDIATE` takes the write
lock before the cash and position reads, so the loop cannot value a portfolio mid-trade and
cannot append a chart point for a state that never existed. This is `_apply_trade`'s shape
(D-01) applied to the second writer, and `busy_timeout=5000` absorbs the contention.

A `None` from `get_latest_snapshot` means write, not skip: there is nothing to compare against,
so the honest answer is to record. A seeded database always has the seed snapshot, so this
branch is reached only on a database whose snapshot rows were removed — it costs one `is not
None` and removes an entire class of "the chart is empty and nothing ever fills it" failure.

Define `async def record_snapshot(db_path: Path, cache: PriceCache) -> bool` — the loop body,
separately callable so every test drives a real write without waiting 30 seconds and without
patching the interval. It builds `prices = {ticker: update.price for ticker, update in
cache.get_all().items()}` on the async side and passes the plain dict inward (D-02): the executor
function never touches `PriceCache`, stays pure over its arguments, and is testable with literal
dicts. Then `return await run_db(db_path, _record_if_changed, prices)`.

Define `async def snapshot_loop(db_path: Path, cache: PriceCache) -> None`: a `while True:` that
awaits `asyncio.sleep(SNAPSHOT_INTERVAL_SECONDS)` **first** and calls `await
record_snapshot(db_path, cache)` second. The sleep-first ordering is load-bearing, not stylistic:
it is the second of RESEARCH Pitfall 1's two independent mitigations, and it means a test app
that lives for milliseconds never reaches a write even if the fixture guard in Task 2 were ever
lost. Say that in the function docstring. Log at `logger.debug` when a row is written, using
`%s`-style lazy formatting — a message every 30 seconds does not belong at info level.

Catch nothing. A broad error-swallowing block that logs and continues would leave a loop that
looks alive and records nothing, and the resulting gap in history reads as a flat portfolio
rather than a broken recorder. The project's rule is raise, don't swallow; a failure surfaces on
the task itself, and Task 3's shutdown path handles a task that is already done.

Then create `backend/tests/services/test_snapshots.py`, following `tests/db/test_queries.py` and

databases under `tmp_path` seeded through the normal path (never `:memory:`), one grouping class

`TestSnapshotLoop` proves the sleep-first ordering without waiting: launch

## Trust Boundaries

| Boundary | Description |
