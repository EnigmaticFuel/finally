<objective>
Write the one committed command that proves the phase, and run it.

Purpose: D-15 requires verification be a re-runnable script plus human UAT, not manual UAT alone and not pytest. The script becomes the foundation Phase 7's Playwright E2E suite layers on rather than duplicates, and it is what makes "the walking skeleton works" a claim anyone can re-check rather than a claim that was true once on one machine.

Two things shape the design. First, `backend/tests/test_main.py` already contains most of this assertion set - including the non-obvious one, where `/api/nope` with a `text/html` Accept header correctly returns 200 rather than 404. That is the SPA fallback being Accept-gated, and a smoke check written from scratch would report it as a bug. Port those assertions rather than re-deriving them. Second, the script drives the container through the platform's own start and stop scripts, which is what makes D-13's claim - that putting the readiness gate in the start script means the smoke check inherits it instead of re-implementing a wait - literally true.

Output: `scripts/smoke_check.py`, a stdlib-only PEP 723 script run as `uv run scripts/smoke_check.py`, plus one green run.

Decisions this plan implements: D-15 (committed smoke script over manual UAT alone or pytest), D-02 (the container and a local `uvicorn` serve byte-identical content), D-13 (the readiness gate is inherited from the start script).

Write `scripts/smoke_check.py` as a stdlib-only script with a PEP 723 header (`requires-python = ">=3.12"`, `dependencies = []`) above the module docstring, run as `uv run scripts/smoke_check.py`. This honours the project's `uv run` only rule and, unlike a `.sh` plus `.ps1` pair, gives one implementation of the assertions instead of two that drift - the same argument D-14 used against `docker-compose.yml`.

Stdlib rather than `httpx` is a deliberate choice with two reasons: the script lives outside the backend uv project so it has no access to the backend's dev dependencies, and `urllib` reads N lines from the SSE stream and closes, which sidesteps the `curl -N --max-time` problem where the tool exits 28 on precisely the timeout it was told to hit and every caller has to whitelist a failure code.

Structure it as a sequence of small named single-purpose functions with full type hints, `from __future__ import annotations` first, module-level `SCREAMING_SNAKE_CASE` tunables instead of magic numbers, and a thin `main()`. The house style is short functions carrying their reasoning in docstrings, not one long procedural body.

`start_container(build: bool)` and `stop_container()` shell out via `subprocess` to the platform-appropriate script selected on `sys.platform`: `scripts/start_windows.ps1` and `scripts/stop_windows.ps1` through `powershell -NoProfile -File` on `win32`, `scripts/start_mac.sh` and `scripts/stop_mac.sh` through `bash` elsewhere. Check the return code and raise on non-zero. This is what inherits D-13's readiness gate - the start script does not return until `/api/health` has answered 200, so the smoke check needs no wait logic of its own, and a regression in either start script fails the smoke check rather than hiding behind a duplicated timer.

Then the serving assertions, each its own function:

`check_health()` - `GET http://localhost:8000/api/health`, assert 200, assert the `content-type` begins `application/json`, parse the body and assert the key set is exactly `{status, market_source, tickers_cached, newest_price_age_seconds}` - four keys, no more, the same set `test_main.py` pins. Do not assert on `newest_price_age_seconds` being a number: it is `None` until the first price arrives.

`check_static_page()` - `GET http://localhost:8000/`, assert 200 and a `content-type` beginning `text/html`, and assert the body is byte-identical to the host file `backend/static/index.html`. That equality is D-02's contract made checkable: the container and a local `uvicorn` serve the same page because both resolve to the same committed placeholder, and it simultaneously proves the Node stage's output actually reached the image through `COPY --from=frontend` (DOCK-01).

`check_api_not_shadowed()` - the mount-order assertion, ported verbatim in meaning from `test_api_not_shadowed`. Request `/api/nope` with an explicit `Accept: application/json` header and assert 404 with a JSON content type. Then request the same path with `Accept: text/html` and assert **200**, with a docstring recording why: the SPA fallback is Accept-gated, `fetch()` sends `*/*`, so the frontend's own calls always land in the JSON case, and a browser navigation to an unknown path correctly gets the app shell. This is correct behaviour and not a defect - write that down, because the next reader's instinct will be to "fix" it. This assertion is what proves the highest-risk property in the architecture survived containerization: a static mount registered before the routers would shadow every `/api/*` route and 404 the whole API while the page still looked fine.

`check_sse_stream()` - open `GET /api/stream/prices` with `urllib`, assert the `content-type` begins `text/event-stream`, then read lines under a hard bound (a module constant, never an unbounded loop), collecting non-blank frames. Assert the first frame is `retry: 1000` and that at least one frame begins `data: `. Close the response as soon as the assertion is satisfiable.

`check_single_worker()` - the DOCK-06 pair, run through `subprocess`: `docker inspect finally-app --format {{json .Config.Cmd}}` must contain `--workers` followed by `1`, and `docker top finally-app` must produce exactly one line whose command contains `app.main:create_app`. Both halves are needed - the first proves the image's intent, the second proves the running container's fact, and only the second would catch a supervisor or reload watcher introduced by a future base-image change.

`check_env_delivered()` - parse the root `.env` for non-comment `KEY=` lines, and for each key run `docker exec finally-app printenv KEY` and compare to the host value. Compare in code and never print either value on any path, including the failure path - the assertion message names the key only. Then assert `/app/.env` does not exist in the image via `docker run --rm --entrypoint sh finally-app:latest -c 'test ! -f /app/.env'`, proving no credential reached a layer.

Every failure must print which named check failed and what it expected versus what it got, then exit non-zero. No emojis in any printed string. Do not wrap the HTTP calls in speculative `try`/`except`: a connection error at this point is a genuine failure the script should surface with its traceback, and swallowing it is exactly the defensive programming the project prohibits.

Do not add any of these assertions to `backend/tests/`. D-15 rejected that explicitly: folding them in would put a Docker daemon dependency inside a suite that today runs in seconds without one, and every future phase would pay that on every run.

Read `users_profile.created_at`, `users_profile.cash_balance` and `COUNT(*)` from `watchlist` twice: once from the host file `db/finally.db`, and once from inside the container via `docker exec finally-app python -c ...` using the app's own `DB_PATH`. `check_stop_is_idempotent()` - run stop, assert exit 0 and that no container named `finally-app` exists in any state; run stop again, assert exit 0. A non-zero second stop would break the safe stop-then-start pattern.
