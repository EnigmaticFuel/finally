<objective>
Give the user one command per platform that reaches a working terminal, and make running it twice as safe as running it once.

Purpose: ROADMAP success criteria 1 and 3 are entirely about this pair of scripts. Criterion 3 - "running start twice, or stop twice, is safe and produces the same result" - is not a nicety: an accidental second `start` that stopped and recreated the container would drop every open SSE connection and reset every ticker's session open price, which is exactly the state the header and the watchlist change column are computed from. Criterion 2 depends on `stop` never touching `db/`.

Output: four committed scripts under `scripts/` - the first `.sh` and the first `.ps1` files in this repository, and therefore the first real consumers of the `.gitattributes` line-ending rules Phase 1 committed for them.

Decisions this plan implements: D-07 (`--env-file .env` on the run line, no second mount), D-09 (start is idempotent without recreating), D-10 (build when missing or when `--build` is passed, and print the image and its build time), D-11 (print the URL, never open a browser), D-12 (stop removes the container, reports nothing-to-stop and exits 0, never touches `db/`), D-13 (the readiness gate lives in the start script).
</objective>

Write the Windows pair as a line-for-line behavioural mirror of the Task 1 scripts. Same order of checks, same printed strings, same exit codes. D-09 and D-12 require identical behaviour on both platforms, and the promote decision recorded above makes the lifecycle contract - not either script - the thing being implemented twice.

Target **Windows PowerShell 5.1** as the floor. This is not a portability preference: `pwsh` is absent on this machine and 5.1 is the only host installed. That rules out three things a PowerShell 7 habit reaches for - the ternary `? :`, null-coalescing `??`, and `Invoke-WebRequest -SkipHttpErrorCheck`, none of which exist in 5.1.

Never write bare `curl` in a `.ps1`. In Windows PowerShell 5.1 `curl` is a built-in alias for `Invoke-WebRequest`, so a readiness gate written as `curl http://localhost:8000/api/health` silently invokes a different command and its `-s` / `-o` / `--max-time` flags are parsed as PowerShell parameters. Use `Invoke-WebRequest -Uri 'http://localhost:8000/api/health' -UseBasicParsing -TimeoutSec 2` instead. `-UseBasicParsing` also avoids 5.1's Internet Explorer engine dependency.

Wrap that call in `try`/`catch`. **This `try`/`catch` is required control flow, not defensive programming, and the project's no-defensive-programming rule does not apply to it:** in 5.1 a non-2xx response throws a terminating `System.Net.WebException`, and the clean alternative (`-SkipHttpErrorCheck`) does not exist in this host. A readiness gate that polls an endpoint which is legitimately not-yet-ready has to catch that throw or it cannot loop. Keep the catch body empty and let the deadline check outside the loop own the failure path.

Check `$LASTEXITCODE` explicitly after every `docker` invocation and exit non-zero on failure. `$ErrorActionPreference = "Stop"` governs cmdlet errors, not native executables: a failing `docker.exe` sets `$LASTEXITCODE` and nothing else, so without an explicit check the script would sail past a failed `docker run` and print `http://localhost:8000` for a container that does not exist. Note that `set -euo pipefail` in the bash pair is not symmetric with this, which is exactly why the same explicit checks must appear in the same places in both scripts if their behaviour is to stay identical.

Mirror the same container detection (`docker ps -q --filter "name=^finally-app$" --filter status=running`, emptiness as the test), the same build-if-missing-or---build policy, the same unconditional image-tag and `docker image inspect --format '{{.Created}}'` print, the same `docker run` argument set including `-p 127.0.0.1:8000:8000`, `-v` for the repo's `db/` directory and `--env-file`, the same 60-second bounded readiness poll with `Start-Sleep -Seconds 1`, the same `docker logs --tail 40 finally-app` on timeout, and the same final `http://localhost:8000` print with no browser launch. Accept the same single `--build` argument.

Resolve the repository root from `$PSScriptRoot` so the `db/` mount and `.env` paths are correct regardless of the caller's working directory, and pass the host side of the `-v` argument as a Windows path.

`stop_windows.ps1` mirrors `stop_mac.sh`: query for the container in any state, print nothing-to-stop and `exit 0` if absent, otherwise `docker stop` then `docker rm` with `$LASTEXITCODE` checked after each. It touches `db/` in no way at all.

Both files must be stored with CRLF endings - `.gitattributes` already pins `*.ps1 text eol=crlf`. No emojis in any `Write-Host` string.
